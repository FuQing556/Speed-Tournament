# Speed Tournament — 单机手游设计方案 v0.1

状态：规划提案，尚未实现或验证。本文中的数值与性能预算属于起始目标，不代表当前工程实测结果。

## 1. 已确认约束与本版假设

已确认：交付单机手游；5～6个可选球体角色；5～6张固定地图；支持重复挑战、分岔与高低差；没有现成赛车和整张地图模型；可以原创技能，不要求逐项复刻《极速追影》。本稿以6个角色、6张地图规划完整首版。

采用此前讨论的自动前进、左右变道、专属技能与通用冲刺。地图在编辑器内辅助制作并烘焙，保存为资产，比赛期间加载固定结果。不同地图、不同模式均有独立、可识别的配置。

工作假设：横屏；Android优先验证，逻辑与数据保留iOS适配空间；完全离线；首版不配置广告、内购、体力、每日签到或在线排行榜。不预估工期和实际可玩时长，待原型与试玩数据明确后再排期。

现有工程：Unity 6000.6.0f1、URP 17.6.0、Input System 1.20.0，基本没有玩法代码。当前依赖表未列出Splines、Cinemachine和Addressables；本设计不预先依赖这些包，具体选型在技术验证时确定。

## 2. 产品体验与首版边界

一句话体验：驾驶有不同能力的球体，在立体闭环赛道中选择路线、连续利用补给、避障或突破障碍，赢得杯赛并刷新个人纪录。

三项体验目标：

- 操作能快速学会，但入弯前的准备、技能时机和分支选择值得反复练习。
- 相同地图重复挑战有可积累的经验；更好成绩主要来自玩家操作与判断。
- 一局约90～150秒，一组杯赛约5～8分钟。实际通过赛道长度、速度和圈数共同校准。

| 内容 | 完整首版目标 | 范围说明 |
| --- | --- | --- |
| 可选角色 | 6个 | 共用球体基础结构，以外壳、装饰、尾迹与技能区分 |
| 固定地图 | 6张 | 同一科幻竞速世界；各自有完整路线、地标和玩法主题 |
| 同场车辆 | 玩家+5辆AI | 未解锁角色也可以作为对手出现 |
| 生涯赛事 | 12场 | 六张地图各有标准与进阶赛事；复用地图，保留各赛事固定配置 |
| 杯赛 | 3组，每组3场 | 固定地图组合，累计积分；支持场间保存 |
| 计时挑战 | 6张地图 | 无AI，固定补给与障碍；按角色、规则版本分别记录 |
| 练习 | 已解锁地图 | 无晋级压力，可自由选择已解锁角色 |
| 路线能力 | 闭环、坡道、高架、分岔与汇合 | 首版主路线保持连续路面；可控跳跃、倒挂与360度扭转暂缓 |

首版不制作地图编辑器给玩家使用，也不做随机拼图地图、联机、开放世界、写实车辆物理或完整幽灵录像。若以后增加随机挑战，应单独建立模式，不改变现有固定地图。

## 3. 游戏周期闭环

### 3.1 从第一次启动到通关

1. 首次进入：默认画质、音量和操控设置；用第一张地图的一小段做可跳过教学。
2. 初始内容：一个角色、第一场标准赛事。教学跳过不会造成存档或解锁断档。
3. 标准生涯：六张地图按顺序推进；取得前三解锁下一场。
4. 角色解锁：完成第二至第六张地图的标准赛事并取得前三，依次获得其余五个角色；第一场主要验证教学成果。
5. 第三张标准地图通过后，开放初阶杯；第六张通过后，开放进阶杯和六场进阶生涯赛事。
6. 初阶杯、进阶杯均取得总积分前三，开放冠军杯；赢得冠军杯获得明确的冠军结算与通关标记。
7. 通关后继续补满赛事星级、杯赛金杯、六张地图的各角色个人纪录与外观奖励。

解锁条件形成单向关系：标准生涯推动地图与角色开放，杯赛推动冠军目标。进阶生涯与计时挑战提供进一步挑战，不要求全满星才能看见结局。

地图解锁时，其练习和基础计时挑战同时开放。计时参考目标在实测后制定，不先凭空填写不可达的金牌时间。

| 杯赛 | 固定地图顺序 | 开放条件 |
| --- | --- | --- |
| 初阶杯 | 01 → 02 → 03 | 标准生涯03取得前三 |
| 进阶杯 | 04 → 05 → 06 | 标准生涯06取得前三 |
| 冠军杯 | 02 → 04 → 06 | 初阶杯与进阶杯均取得总积分前三 |

杯赛每个分站引用独立的赛事配置，可使用对应地图的进阶障碍布局与AI难度。开始前明确显示地图组合和难度，整组比赛不临时随机更换。

### 3.2 单次游玩的闭环

进入主页看到“当前可推进赛事”和最近个人纪录 → 选择推进生涯、参加杯赛或挑战纪录 → 选角色 → 比赛 → 看到名次、成绩变化与新解锁 → 一键重试、下一场或回主页。

每次结束必须给玩家一个明确反馈：晋级了、首次得星了、刷新纪录了，或者在哪里损失了时间。重试保持上次地图和角色，不重新走完整菜单。

### 3.3 奖励与长期目标

采用赛事星级、杯赛奖杯和外观解锁。首版不设永久属性升级和可反复刷取的货币，避免靠堆数值突破关卡，也减少经济系统维护成本。

| 奖励对象 | 获得规则 | 重复挑战规则 |
| --- | --- | --- |
| 生涯赛事星级 | 完赛1星；前三2星；第一3星；未完赛0星 | 每场保留最高星级，不累加刷取；12场共36星 |
| 新地图与角色 | 达成对应生涯晋级条件 | 永久保留，不消耗星级 |
| 杯赛奖杯 | 按三场总成绩授予金、银、铜杯 | 保留最好奖杯与最好杯赛成绩 |
| 外观 | 累计星级里程碑、金杯、角色计时目标 | 一次性解锁；仅改变外观 |
| 个人纪录 | 有效规则下更快地完成比赛 | 保存最好成绩，并显示本次相差多少 |

星级是已掌握内容的记录，不是消费材料。遇到失败可以立即重试，也能去已解锁地图练习；没有体力、维修费或失败扣款。全收集后仍能玩全部内容，但不把无尽刷取作为单机产品必须完成的目标。

## 4. 游戏玩法闭环

### 4.1 局内循环

观察前方路线和障碍 → 提前选择车道 → 拾取技能点或冲刺能量 → 决定使用或保留 → 获得速度、通行或对抗优势 → 在下一组弯道与补给重新判断。

主要决策由三种取舍产生：近路与补给路线、当前收益与下一危险段、纯速度与稳定通行。每张地图至少安排一个能体现这些取舍的分支，不能全部做成“明显更短且更安全”的单一最优选项。

### 4.2 操控与移动

- 球体自动前进，玩家不控制油门、刹车或自由转向。
- 默认左下方两个变道按钮，右下方专属技能按钮和冲刺按钮；变道每次跨一个相邻车道。
- 变道初始时长约0.20～0.25秒，允许缓存一次后续变道。连续输入、边缘车道和相反方向输入均需在原型中明确测试。
- 专属技能点按施放；通用冲刺按住消耗能量，松开停止。提供点按切换冲刺作为操控选项，两种方式最终产生相同的逻辑指令。
- 开局自动起步，暂不加入抢按倒计时的特殊起步奖励。玩家进入比赛后立即使用普通操作即可。
- 手机输入和编辑器键盘输入统一转成动作指令，不让输入实现直接修改赛车位置。

首版主路以4车道为标准，分支可减为2或3车道。路段连接处显式配置车道映射，界面提前提示可进入的车道；高低层道路不因空间接近而允许横移。

### 4.3 两套局内资源

| 资源 | 获取 | 使用 | 初始调参值 |
| --- | --- | --- | --- |
| 技能点 | 黄色补给每个+1 | 专属技能消耗1点 | 上限3点，开局1点 |
| 冲刺能量 | 彩色补给补充 | 通用冲刺按时间消耗 | 常规上限100，每瓶+35，开局30；持续冲刺约3秒耗尽 |

不要求技能点全部存满才能释放。能量不足时不能启动冲刺，具体最低启动量属于可调参数。资源溢出直接截断，界面给予“已满”反馈；资源不带入下一场比赛。

拾取规则保持可预测：只领取自身扫过的拾取范围内、或技能明确允许吸取的补给。同一个补给不能因为多帧停留或变道而重复领取。若变道实际扫过两个补给，可以取得两个，收益仍按各自类型结算。

### 4.4 速度、碰撞与状态

角色具有巡航速度、提速能力与碰撞恢复性能，数值是平衡参数。用受控的速度曲线驱动车辆，不依赖球体刚体滚动来决定前进。

- 普通冲刺、角色加速和加速带分别提供目标速度或持续效果；目标速度初版取有效加速效果中的最高值，并受统一上限约束，不做无限倍乘。
- 同时使用较弱加速可能浪费持续时间，因此衔接使用是基本技巧。界面应显示当前加速及剩余时间。
- 广告牌造成明显减速；大型障碍造成短暂失控；车辆碰撞造成较轻干扰。具体减速比例和时长由配置控制。
- 撞击可立即压低当前速度，并进入短暂恢复阶段；未结束的加速状态会继续计时，不允许下一帧直接恢复最高速度从而抹去碰撞惩罚。
- 破坏性护盾、穿透状态和普通受击使用明确的优先级表。同一对对象有接触冷却，防止一次贴靠结算几十次伤害或护盾延长。
- 首版碰撞表现以侧倾、闪光和速度损失为主，车辆仍约束在合法路线内。明确设计的路线连接负责跨层，碰撞不把车打进未知道路。

道路减速区属于地面效果，需要在技能配置中明确是否免疫；“免疫碰撞”不自动等于“免疫所有负面效果”。

接触处理顺序固定：先验证道路连通性、有效接触与重复命中冷却；幻影若能穿透该对象则忽略接触；否则由有效护盾拦截并处理破坏/延长；最后才施加普通减速或失控。技能结束不能因特效尚未消失而继续提供保护。

持续技能重复施放使用明确的刷新规则；初版同一技能刷新到基础持续时间，不把剩余时间无限相加。重盾的撞击延长另受单次激活总时长限制。每个技能均有最短再施放间隔，避免同一输入批次消耗全部技能点。

### 4.5 六个原创角色提案

名称为工作代号。下列描述定义差异方向，时长与数值需通过六张地图的测试调整。

| 角色 | 专属技能 | 主要决策与适合路线 | 约束 |
| --- | --- | --- | --- |
| 疾风 | 短时强化加速 | 在可连续通过的路段爆发，衔接普通冲刺 | 碰撞仍有惩罚，不能靠加速免控 |
| 重盾 | 短时无敌并撞毁可破坏障碍；有效撞击延长持续时间 | 主动进入障碍密集线，连续突破 | 延长有单次与总时长上限；同一对象不可反复刷 |
| 脉冲 | 攻击前方一定距离内的合法目标，清障或干扰对手 | 保留技能处理关键堵点或争夺超车 | 限定当前道路及连通方向，不隔层命中；以脉冲特效表现 |
| 引力 | 短时扩大邻近车道补给拾取范围 | 选择补给丰富的路线，为后续持续冲刺准备资源 | 不跨分支或上下层吸取；每个补给仅领取一次 |
| 幻影 | 短时穿过车辆和指定障碍，保持路线与速度 | 穿越拥堵段，并为出技能后的车道位置提前准备 | 不破坏障碍、不能跨越断路，不免疫地面减速区 |
| 蓄能 | 回充冲刺能量，配合较高能量上限 | 在长距离缺补给路段管理能量，维持节奏 | 峰值速度保守，能量已满时施放会浪费收益 |

六个角色使用同一套移动、拾取与比赛规则。差异只来自车辆配置与技能组合，不编写六套控制器。禁止靠永久升级让某个角色全面优于其他角色。

计时挑战按角色分别记录，避免要求六种完全不同的技能在所有地图上都跑出相同极限成绩。生涯中则要求每个角色都能在熟练操作下完成已开放赛事。

## 5. 六张固定地图与制作方法

### 5.1 赛道提案

| 地图 | 主体布局 | 分支取舍 | 高低差与辨识物 |
| --- | --- | --- | --- |
| 01 起航环线 | 宽弯、直道、短S弯 | 内侧短线补给少，外侧长线补给多 | 小坡、起点拱门、显著环形终点塔 |
| 02 广告回廊 | 狭长弯道与移动广告牌 | 密集障碍短线与安全绕行线 | 连续缓坡、大型悬挂广告框 |
| 03 高架双环 | 两层环线，通过坡道连接 | 高架近路与下层补给线 | 上下跨越、立柱与不同颜色的层级灯带 |
| 04 工业螺旋 | 大半径爬升与下坡回环 | 平稳长线与窄弯短线 | 高塔、管线、螺旋坡道；路面不倒挂 |
| 05 夜港交错 | 隧道、交叉高架与较长冲刺段 | 开阔高速线与有掩体的补给线 | 明暗切换、港口剪影与连续桥墩 |
| 06 星环决胜 | 综合前五张地图的操作要求 | 两次有先后影响的路线选择 | 终场大拱门、高位回望与下坡冲线 |

第一张地图每圈一个简短分支，其余逐步增加，首版单圈最多两个决策明确的分岔口。高低差服务于预判与路线差异，避免连续陡坡遮挡所有前方信息。

六张地图共用路面、护栏、支撑、拱门、广告牌和少量环境模块，但每张地图都有独立轮廓和地标，不能只换配色。

### 5.2 编辑器内生产流程

绘制道路曲线并指定路宽、车道数与倾斜 → 配置分岔/汇合连接模块 → 放置障碍、补给、检查点与装饰 → 烘焙道路网格和行驶采样表 → 校验 → 在实际比赛中跑圈。

道路烘焙器只解决可重复的铺路工作。分岔口、汇合口、支撑和特殊连接由固定模块或人工调整处理。第一版工具只需控制点编辑、场景预览和烘焙按钮，不先开发完整可视化节点编辑器。

输出分成静态渲染资产和行驶数据。比赛加载已烘焙结果；不会每圈重新生成，不会每次开局随机改变路线。更新地图必须生成新内容版本。

### 5.3 道路拓扑与闭环

地图表示为有方向的道路图：普通路段、分岔节点、汇合节点、检查点与终点。每条道路保存自身长度和等距离采样数据，每个连接保存允许的进入车道与离开车道。

角色状态包含当前道路ID、道路内距离和横向位置。到达路段末尾时，将本次移动的剩余距离继续应用到合法后续路段；不能因为过接缝而损失一帧距离。终点连接回起始路段，并在合法通过一整圈后增加圈数。

首版分支均顺向汇回同一条赛道，不设计支路内部无限绕圈、逆行和必须持有某技能才能逃出的区域。岔路口选错是合法路线选择，不会形成软锁。

烘焙检查包括：起点到终点可达、每个分支能汇合、检查点顺序有效、路段连接的位置/切线/朝向连续、首尾接缝、合法路宽、最小弯曲半径、足够的高架净空和可用车道映射。道路朝向包含连续的上方向，不能仅靠首尾位置相同就宣称闭环正确。

### 5.4 分岔条件下的名次与防漏判

对比原始累计米数会错误奖励长路。使用“已完成圈数 + 规范赛道进度”。两条分支在入口、出口共享进度锚点，各自实际距离映射到这一段规范进度；必要时增加中间锚点。

短路实际较短，因此同样速度能更快推进到汇合点，保留捷径收益。岔路内的即时名次是规则定义的进度比较；最终名次按合法越过终点的时间确定。

检查点只在当前道路的合法前进过程触发，空间上跨越另一层终点不会计圈。一次模拟步可能经过多个路段、补给和检查点，必须逐段处理整段移动，而非只看这一帧结束位置。

### 5.5 布局公平性

- 普通行驶条件下始终有可通行路线，不强制玩家携带某个角色技能。
- 危险提示距离按最高可能速度设计。起始目标是在到达关键障碍前提供至少约1.5秒可识别时间，并进一步计入实际变道时间；由真机画面验证。
- 连续动作之间留出足够距离，避免出现操作时长上无法完成的左右切换。
- 移动障碍的初始相位与运动周期固定，按比赛逻辑时钟运行。相同赛事重复挑战可学习其规律。
- 相同颜色在所有地图上表达相同功能；另用形状、箭头和图案区分，避免仅靠颜色读信息。

## 6. 模式规则与完整局内流程

### 6.1 模式区别

| 模式 | 胜利/记录规则 | 对手与变化 | 保存点 |
| --- | --- | --- | --- |
| 标准/进阶生涯 | 完赛给星；标准前三推进解锁 | 5个AI；对应赛事使用固定配置 | 完赛后提交星级、成绩与解锁 |
| 杯赛 | 三场总积分决出名次 | 固定名单与难度；开始前选角色并锁定至杯赛结束 | 每场结算后保存积分和下一场索引 |
| 计时挑战 | 合法完成全部圈数，争取更短用时 | 无AI；固定补给和障碍，正常使用角色技能 | 完赛后保存对应角色与规则版本的最好成绩 |
| 练习 | 可跑完整比赛或自由退出 | 默认无AI，可使用常规资源配置 | 只保存偏好；不发赛事星级或竞速榜成绩 |

生涯和杯赛成绩不写入纯计时挑战榜。排行榜只展示本地个人成绩及预设参考目标，不暗示存在真实玩家联网排名。

杯赛积分初案：第1～6名分别10、8、6、4、2、1分；未完成0分。总分相同时，依次比较分站第一次数、三场总用时、最后一场名次。超时未完成者用赛事配置的截止时间加未完成罚时参与总用时比较；必须有至少一场有效完赛才授予奖杯。

### 6.2 比赛状态机

选赛事/角色 → 加载当前地图 → 校验配置并预热 → 准备界面 → 倒计时 → 比赛中 → 玩家完成/超时失败 → 结算计算 → 保存结果 → 结果界面 → 重试/下一场/返回。

| 状态 | 必须完成的责任 | 离开条件 |
| --- | --- | --- |
| 加载 | 读取单张地图和规则、创建车辆、设置对象池 | 必要资源就绪，否则显示可重试的错误 |
| 准备 | 初始化车道、资源、AI和计时，展示目标 | 玩家开始 |
| 倒计时 | 禁止提前移动，清理残留按键状态 | 同一逻辑时刻放行全部车辆 |
| 比赛中 | 更新移动、技能、拾取、检查点与名次 | 玩家完赛、赛事截止或退出 |
| 暂停 | 冻结玩家、AI、障碍、技能和比赛时钟 | 恢复前重新倒计时；暂停时不消费技能资源 |
| 完成展示 | 锁定玩家终点成绩，控制镜头和结束反馈 | 生涯可结算；杯赛等待其余车辆完赛或达到截止 |
| 结算与保存 | 生成唯一结果，计算星级/积分/解锁，提交存档 | 提交成功；失败允许重试保存并明确告知 |
| 结果界面 | 展示可解释的成绩与下一步 | 重试、杯赛下一场或返回菜单 |

杯赛玩家先到终点时，短暂展示其余车辆结果。剩余模拟可以在固定逻辑步长下加快处理，需限制每帧工作量；超过赛事截止时间则记为未完成。不能让结果页无限等待落后AI。

同一模拟步内有多车过线时，按该步内实际越线比例细分终点时间。若仍相同，按预先定义的固定席位顺序作为最后技术决胜项，避免结果随帧遍历顺序改变。

### 6.3 中断、退出与重试

- 手动暂停、来电或切后台：进入统一暂停状态，清除按住冲刺/变道的残留输入。恢复需短倒计时；后台不继续比赛。
- 杀进程：首版不承诺恢复到赛道中间；重开本场。已提交的生涯进度和杯赛已完成分站必须保留。
- 杯赛只在结算页进入下一站。下一站加载中断时仍恢复到该站准备状态；上一站不可重复领取或重复计分。
- 生涯/计时主动退出或重试不发奖励。杯赛允许重开当前未结算分站，不允许通过返回操作重算已经提交的分站。
- 放弃整组杯赛需要明确操作确认；保留已取得的永久解锁和历史最佳杯赛成绩，清除当前杯赛进度。
- 超时失败时显示原因，可直接重试；损坏或加载失败的配置不能进入比赛。
- 结算写盘失败时，保留内存中的待保存结果并允许重试；不能显示“已保存”后悄悄丢进度。

## 7. 赛道对象与AI规则

### 7.1 补给、障碍与复位

补给为“每辆车、每圈可领取一次”，不被AI永久抢空。玩家画面只呈现自己的可领取状态；AI按各自状态计算资源。这样重复练习的补给线稳定，计时模式也更容易比较。

可破坏障碍属于共享赛道状态，破坏后所有车辆都能受益。按固定冷却复位，复位时若仍有车处于占用范围则延后，避免障碍在车内重生。模式配置明确该规则；计时挑战没有AI造成的随机清障。

每次重试必须重置全部领取标记、障碍状态与相位、技能计时、AI随机数状态、圈数、检查点和暂存统计。重试后的状态等价于新开本场。

### 7.2 AI

AI使用与玩家相同的道路、移动、资源和碰撞规则，输出变道与技能指令。位置更新持续进行，选路决策采用较低频率，初始候选约10Hz，再通过测试调整。

AI对可选车道/路线评估前方危险、补给需求、角色技能收益和对手位置。不同难度主要改变反应延迟、预判距离、选道误差与技能使用能力，不靠瞬移或无限资源获胜。

首版不启用隐藏追赶加速。每场使用固定初始种子与AI性格；种子、规则版本及初始状态共同决定初始行为。玩家干扰仍会改变后续比赛，不承诺AI整场每次走相同路线。

AI不能读取玩家尚未提交的输入，也不能把远处不可见路段上的所有危险当成即时已知信息。加入避让滞后，避免连续左右抖动；通过汇合车道规则避免AI堵死在分支出口。

## 8. 数据架构

### 8.1 四类数据明确分离

| 层次 | 保存内容 | 生命周期与载体 |
| --- | --- | --- |
| 制作数据 | 路线控制点、连接、摆放、技能与赛事配置 | Unity编辑器资产，便于修改与校验 |
| 烘焙数据 | 路面网格、道路图、距离采样表、空间索引、检查点映射 | 随包发布；运行时只读 |
| 对局状态 | 位置、速度、资源、状态、AI、道具领取与障碍复位 | 每场初始化，存在内存，不写回配置资产 |
| 用户存档 | 解锁、星级、个人纪录、设置、未完成杯赛 | 本地带版本的存档；不保存Unity对象引用 |

ScriptableObject用于静态配置，运行时变化放入独立状态对象。存档和跨资产引用使用稳定ID，不依赖中文显示名、数组位置或场景对象名称。

### 8.2 主要配置与字段

| 数据 | 主要字段 | 关系 |
| --- | --- | --- |
| CharacterDefinition | id、显示文本键、外观ID、速度/恢复参数、能量上限、skillId、解锁条件ID | 指向技能与表现资源 |
| SkillDefinition | id、消耗、目标筛选、范围、效果列表、持续/叠加/刷新规则、表现ID | 组合已有逻辑效果 |
| TrackDefinition | id、内容版本、场景/资产引用、道路图ID、地标、建议圈数 | 地图资产入口 |
| BakedRoadGraph | 路段ID、节点、实际长度、采样、连接车道映射、规范进度锚点、检查点 | 车辆移动和名次的共同依据 |
| EncounterLayout | id、版本、补给、障碍、移动周期、复位规则 | 引用固定道路ID和道路内距离 |
| RaceDefinition | id、trackId、layoutId、rulesetId、圈数、AI配置、种子、截止时间、奖励ID | 一场可重复赛事的完整描述 |
| CupDefinition | id、有序raceId列表、积分与平分规则、角色锁定规则、解锁条件 | 串联三场比赛 |
| RulesetDefinition | id、版本、模式、资源规则、辅助选项、时间规则、纪录类别 | 防止不同规则成绩混用 |
| ProgressionDefinition | 解锁条件、条件组合、星级里程碑、奖励内容 | 使用固定类型条件，不首创复杂脚本语言 |
| QualityProfile | 内部渲染比例、阴影/后处理/特效档位、帧率目标 | 不改变逻辑移动或碰撞 |

道路上的对象位置采用“路段ID + 距离 + 横向位置/车道”，高低层对象不会混用。编译后的目录负责ID解析；开始比赛前解析必需引用，比赛热路径使用数组索引或紧凑句柄，避免持续字符串查找。

### 8.3 对局状态与事件

RaceState：比赛ID、运行状态、逻辑步编号、比赛时钟、车辆状态数组、赛道动态状态、随机状态、待输出事件。

RacerState：角色ID、当前道路、道路内距离、横向位置及变道过程、速度、资源、生效状态、圈数、检查点进度、完赛状态、越线时间。

RaceResult：resultId、赛事与规则版本、角色、有效性、名次、最终用时、统计、奖励增量；杯赛另包含杯赛运行ID及分站索引。

表现层消费“拾取成功、命中、状态变化、名次变化、过检查点、完赛”等事件。表现没有权力授予资源或决定终点名次；特效被画质档位关闭后，逻辑结果保持一致。高频事件使用复用缓冲，避免每帧创建临时对象。

### 8.4 推荐代码模块

- Race.Core：道路进度、移动、碰撞、技能、AI、名次与比赛时钟；尽量使用可独立测试的C#逻辑。
- Game.Flow：界面间流程、生涯推进、杯赛编排、创建比赛请求与提交结果。
- Game.Data：配置定义、目录、加载后的只读数据与规则校验。
- Game.Persistence：存档DTO、版本迁移、备份恢复与幂等提交。
- Game.Presentation：Unity场景、球体表现、相机、输入适配、UI、音效和特效。
- Game.Editor：赛道制作、烘焙和内容检查；不进入手机版运行时代码。

基础依赖方向为流程调用比赛逻辑，逻辑输出状态供表现读取。以少量明确模块组织，不预先上ECS、网络同步、复杂依赖注入或通用插件框架。

### 8.5 本地存档与纪录

存档包含schemaVersion、内容兼容版本、profileId、单调递增修订号、已解锁ID、12场最高星级、杯赛最好结果、个人纪录、设置、当前杯赛状态及最近的结算提交标记。

纪录键至少包含地图ID及版本、布局ID及版本、角色ID、规则版本、圈数、会影响比赛的辅助选项。速度、碰撞或技能平衡改变时提高规则版本；旧纪录保留为旧版记录，不混入新榜。显示名或纯装饰改变通常不需要使成绩失效。

用逻辑步编号和越线子步比例计算原始用时；保存整数微秒等统一精度值，最后才格式化显示。内部比较不依赖屏幕上保留两位小数的文本。

结算先生成唯一结果，再在同一份存档快照里完成星级、解锁、奖杯、杯赛推进与提交标记更新；使用临时文件、安全替换及备份恢复机制，并在目标平台验证断电/杀进程行为。不能分开保存“发奖励”和“已发奖励”。

重复提交相同resultId或同一杯赛已完成分站不再计奖/计分。一次性解锁与最高星级天然使用幂等更新，提交标记按检查点清理，避免存档无限增长。

读取存档优先校验版本与完整性，失败时尝试备份；迁移前保留原件。未知内容ID按规则忽略或保留，杯赛引用的赛事已不兼容时明确结束该旧杯赛，已获得永久进度不回收。两份存档均损坏时告知玩家，不能静默用空存档覆盖。

## 9. 性能设计与验收

### 9.1 前提

道路通过程序制作不自动意味着更快或更慢。运行时的主要成本是可见几何、材质与透明覆盖、灯光、特效、UI、脚本和资源管理。目标手机尚未指定，以下为设计预算，必须在真实设备上验证。

中档设备以稳定60帧为目标，低档设备提供稳定30帧档。先选定最低支持机与一台中档机，再以其持续运行表现确定交付边界，不能用编辑器帧率替代。

### 9.2 比赛逻辑

- 固定逻辑步长初案60Hz，画面按设备帧率插值；低画质不减少行驶距离或改变技能持续时间。
- 道路位置从烘焙的距离表采样。每步只处理6辆车及附近候选对象，AI较低频决策但持续移动。
- 道路对象按路段与距离区间建立索引，碰撞检查覆盖整个已移动区间；不全图扫描，不依赖海量物理触发器。
- 赛车之间使用当前道路连通性、相对前后距离和横向范围判断。上下层仅在视觉空间接近时不发生碰撞。
- 对车辆、常用特效与音源预热对象池。池耗尽时可省略次要视觉反馈，不能省略伤害、拾取或结算。
- 比赛热路径避免LINQ、临时集合、逐帧字符串拼接和临时事件对象。以Profiler检查可控脚本的逐帧GC分配，不能只凭代码风格声称“零GC”。

固定步长也需要处理积压：每帧限制追赶工作量，未处理的步保留，不能靠直接丢掉时间来漏过障碍。持续积压或系统长时间中断时进入恢复暂停，保存当前比赛状态，重新建立时间基准后倒计时恢复。逻辑时钟同步暂停；频繁触发恢复暂停说明设备不达性能门槛，不作为日常低帧解决办法。

### 9.3 渲染与资源

- 一次只加载当前地图，不同时保留六张完整场景。重试复位当前内容，换图才卸载不再使用的资源。
- 道路烘焙成适当长度的静态网格段，支持视锥剔除；避免整张地图合成一个永远可见的大网格，也避免每米一个渲染对象。
- 高架与分支采用保守的可见范围。不能只按当前路段关闭其他道路，否则可能在下层看不到本应可见的上层；剔除策略以相机实际可见性校验。
- 共享路面和装饰材质。批处理/实例化是否生效以实际渲染统计为准，不假定开启某个选项就能合并所有绘制。
- 大多数表面采用不透明材质；控制透明护罩、叠加速度线、粒子和泛光。发光外观不要求每段灯带都放置实时灯光。
- 限制实时阴影和光源；低档关闭高成本后处理，简化远景和特效。球体阴影可用廉价投影表现。
- 相机保持前方可读性，随坡度平滑调整；速度感由少量视野变化、近景参照物、音效和尾迹共同提供，不依赖昂贵运动模糊。
- HUD拆分高频与低频更新；只在值变化时更新能量、名次和状态。显示计时可以降频刷新，实际计时仍使用统一逻辑时钟。
- 赛前完成当前角色、障碍与技能主要材质的首次使用准备，并单独测试第一次命中特效、第一次进隧道等潜在卡顿点。

### 9.4 起始预算与实测标准

| 项目 | 初始预算或验收内容 |
| --- | --- |
| 60帧档 | 一帧16.67ms；目标CPU主要工作和GPU耗时P95分别控制在约12ms、13ms以内，二者不能简单相加 |
| 30帧档 | 一帧33.33ms；预留温升和系统抖动余量，不把整帧预算用满 |
| 几何/绘制 | 灰盒进入美术阶段的起始预算：可见约15万三角形、约120次绘制调用；这些数值不单独构成性能合格证明 |
| 内存 | 初始目标峰值约600MB以内，最终依据最低支持设备与实际包体确定 |
| 长跑 | 6车、完整道具、最复杂分支和高架视角，连续30分钟记录温升、CPU/GPU、帧间隔P95/P99及异常尖峰 |
| 资源循环 | 连续重试20次、反复切换六张地图，确认内存无持续增长、对象池无持续扩容 |
| 跨帧率正确性 | 同一逻辑步输入序列在30/60帧显示下产生一致比赛结果；另做真实触摸延迟和手感测试 |
| 内容最坏情况 | 所有角色技能同屏触发、汇合口拥挤、移动障碍复位、首轮资源首次出现都单独覆盖 |

画质自动调整采用一段时间的统计与冷却间隔，先降低视觉负担，必要时切到稳定30帧。不能单帧一抖就来回调档。比赛规则、AI速度、碰撞范围和道具密度不随画质改变。

## 10. 可拓展性与修改成本

| 扩展需求 | 应主要修改 | 不应连带修改 |
| --- | --- | --- |
| 第七个角色 | 新角色配置、技能组合、外观和解锁条件 | 排名、移动和存档主体结构 |
| 全新技能机制 | 添加一个目标/效果处理器及表现，再配置角色 | 六个角色各自控制器 |
| 第七张地图 | 路线制作、烘焙、地图注册与赛事配置 | 生涯流程代码和杯赛算法 |
| 新分支路线 | 道路图、连接模块、进度锚点和检查点校验 | 根据世界坐标硬写跨层判定 |
| 新杯赛/难度 | 有序赛事列表、AI参数、奖励条件 | 复制完整比赛状态机 |
| 平衡更新 | 数值与规则版本 | 覆盖或删除全部玩家进度 |
| iOS交付 | 平台生命周期、存储、触控、安全区、图形与包体测试 | 核心比赛规则 |

把“新增配置就能完成的内容”与“需要新增程序能力的内容”分清。例如增加加速持续时间只需配置，加入时间倒流、物理跳跃或自由转向则属于新机制，不能承诺无代码扩展。

内容注册表由制作流程生成或维护，发布前检查重复ID、失效引用、无入口赛事、循环解锁、缺失资源、烘焙过期和不可达检查点。不要让地图数量或角色数量写死在UI数组长度和解锁判断里。

## 11. 玩家可见的信息与表现

主页突出继续生涯、继续杯赛与最近使用的挑战入口。地图选择能看到路线轮廓、主分岔、高低差示意、可选赛事和个人最好成绩。

选角页显示技能用途、速度与容错倾向，并标明解锁条件。不要用难以理解的大量小数代替玩法说明。

局内必须清楚显示名次、圈数、计时、技能点、冲刺能量、当前状态及必要的后方接近提示。小地图展示道路连接和检查点，高低层不能把车辆图标叠成无法区分的一团。

结算展示：本次名次和用时、个人最佳差值、新星级/解锁，以及少量可行动统计，例如障碍碰撞次数、冲刺利用时间和路线选择。不能凭空生成“你本可快多少秒”的精确结论；损失估计只有实现可信统计后才显示。

原创美术以基础球体、外壳分片、环形装饰和尾迹建立角色区别。赛道以模块化路面与护栏为主体，使用少量地标建立记忆。视觉制作逐步加入，同时保持灰盒阶段已经通过的可读性与性能。

## 12. 开发顺序与通过条件

### 阶段A：验证赛道方案

交付一张灰盒固定地图，包含完整闭环、坡道、高架、一个分岔汇合；一个可操作球体与5辆简化AI；支持完整跑圈、排名、暂停、重试以及手机构建。

通过条件：连续跑圈无接缝跳变；分支均可完成；上下层不误碰撞/误计圈；快捷路径名次合理；低帧与高速不漏检查点；真机基础性能达标。若失败，先修正道路/相机/采样方案，不能继续复制问题到六张地图。

### 阶段B：验证玩法与完整游戏闭环

在已通过的地图上加入两种差异明显的角色、补给/障碍、技能、完整结算与存档；配置一组用于验证流程的三场杯赛，场间可以复用灰盒地图。

通过条件：初次进入、比赛、获得进度、解锁、重试、退出重进、杯赛恢复都能闭环；重复结算不重复计奖；玩家愿意因为一次失误或不同路线主动重试。临时复用地图仅用于验证，不计入完整首版六张地图。

### 阶段C：补齐内容

完成6个角色、6张固定地图、12场生涯赛事、3组杯赛和6张地图的计时配置。新增地图逐张通过道路校验和性能检查；每个角色在每张地图上至少完成通行与技能可用性检查。

通过条件：没有角色专属通关死锁，没有一条分支在所有条件下完全无价值；所有解锁都可达，全部模式结算与记录分类正确。

### 阶段D：手游交付

完成正式外观、音效与必要反馈；验证不同屏幕比例与安全区、来电/切后台、杀进程、低电量温升、存档备份恢复、离线首次启动和更新后的存档迁移。

交付候选应能从干净安装开始完成冠军流程，并且保留玩家旧版进度。以目标设备发布构建的持续测试结果决定是否满足60/30帧档承诺；先修复卡顿、存档丢失和流程断点，再考虑额外内容。

## 13. 下一步落地决策

当前足以开始的工作是阶段A的技术验证设计与实现。正式制作内容之前，还需由原型确定目标速度、路宽、镜头距离、变道时长、采样密度和网格分段长度。
